## Scope

PR #18 qualifies the existing T17 Free web slice without changing product contracts, migrations, measurement semantics, provider activation or paid behavior.

- `@axe-core/playwright@4.13.0` is pinned exactly. Its pnpm lockfile entries were generated by GitHub Actions from the real workspace rather than hand-authored; resolver run: `36337129507`.
- Fixture browser tests run with `PRINCESS_WEB_FIXTURES=1` and explicitly exclude the live spec.
- Live browser tests require explicit API/sample/worker-gate configuration, run with `PRINCESS_WEB_FIXTURES=0`, and prove fixture routes are unavailable.
- Automated axe coverage uses the WCAG A/AA tags `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, and `wcag22aa`. An isolated deliberately unlabelled input proves the gate detects a known violation.
- Existing keyboard, responsive, evidence-integrity and privacy/authorization assertions remain independent of axe. Automated scans do not replace manual accessibility review.

## Qualified states

The fixture suite covers start/upload, Free report, report history and empty history, both rejected-evidence integrity states, settings, Swedish 320px report/history layouts, dark mode, reduced motion and cancellation of the destructive account action from the keyboard.

The live suite uses only a generated synthetic handwriting image and executes:

`upload → consent → queued analysis → refresh the same run → release deterministic analysis worker → saved report/evidence → history → PDF export → cross-owner denial → anonymous denial`.

The analysis worker is intentionally held behind a sentinel until the browser has refreshed the queued run, so the test demonstrates reconnect/resume before completion rather than merely reopening an already completed report.

The destructive live runner refuses to reset PostgreSQL unless the caller supplies both an explicitly local `/postgres` admin target and `PRINCESS_E2E_ALLOW_RESET=1`. CI exercises the refusal path before running the live journey.
